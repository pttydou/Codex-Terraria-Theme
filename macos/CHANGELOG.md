# Changelog

## 2.7.2 — stable Composer ownership

- Codex 26.730 的 Composer 不再依赖 `.composer-surface-chrome`；通过稳定的
  `data-composer-surface-variant`、`data-composer-utility-bar-variant` 和直接子级
  `data-composer-layout` 发现并标记当前可见输入面板。
- 首页“项目 / 本地 / 分支”环境栏通过
  `data-composer-home-utility-bar-position` 获得 `.dream-skin-home-utility` 标记，
  不再保留 Electron light shell 的白色横带。
- Composer 视觉样式只依赖 `.dream-skin-composer-surface`，并强制清除原生
  `canvastext` outline；普通 Markdown、标题栏、侧边栏和其他输入控件不受影响。
- 路由切换、热注入和恢复会清理失效标记；探针、早期注入、live verify 与 Windows
  实现同步，并保留旧 Codex 类名作为兼容发现路径。

## 2.6.0.12 — background music continuity

- 环境音乐默认在 Codex 失去焦点、被其他窗口遮住或进入后台时继续播放；只有
  用户明确勾选“Codex 隐藏时暂停”才会暂停。
- 旧的 schema-1 音乐配置若没有该字段，会安全迁移为后台继续播放；已有明确
  设置仍保持不变。
- 本机现有音乐配置可原子更新为后台继续，不需要重新导入 57 首音乐。

## 2.6.0.11 — semantic main-surface ownership

- 不再依赖 Codex 易变化的 `main.main-surface` 类名；注入器根据输入框、原生
  Header、侧栏和实际几何位置识别主内容区，并添加自有标记供 CSS 使用。
- 多层 `<main>` 页面会优先选择真正包含输入框或会话 Header 的内层内容区，
  避免把外层全窗口容器误当作皮肤画布。
- 原生 Header 同样使用语义识别与自有标记；顶部 HUD 移除生命/魔力装饰，
  只保留音乐按钮，彻底避免遮挡 VS Code 与会话操作控件。
- VS Code/打开位置组合按钮使用环境面板底色和高对比前景，不再出现白底浅色
  图标难以辨认的问题。
- 恢复官方外观时同步清理自有主内容标记；探测与回归测试覆盖原生类名消失场景。

## 2.6.0.10 — clickable native-header HUD

- 移除 Terraria 对话页对 Codex 原生 Header 的错误 `z-index: 1`
  覆盖，继续使用原生 `z-30` 堆叠层。
- 修复音乐按钮、生命和魔力 HUD 虽然可见，却被对话滚动容器覆盖并
  无法响应真实鼠标点击的问题。
- 渲染回归测试现在会禁止任务主题再次覆盖 Header 的定位或层级。

## 2.6.0.9 — diagram contrast and exact biome torches

- Mermaid/流程图节点与连线标签使用独立深色前景，不再继承 Terraria 正文的
  米白色文字，修复白色节点中内容几乎不可见的问题；普通 Markdown 仍保持
  当前环境的高对比配色。
- 火把装饰严格遵循火把神恩赐的环境映射。仅以太、地牢、丛林神庙、地狱、
  夜光蘑菇、神圣、腐化、猩红、冰雪、丛林和地下沙漠及其对应细分环境显示火把；
  森林、普通地下/洞穴、太空、海洋、事件与其他小生态不再放置兜底宝石火把。
- 从有火把环境切到无火把环境时会立即撤销属性、释放懒加载素材并隐藏装饰，
  防止上一环境的火把残留；固定主题与全环境随机使用同一规则。

## 2.6.0.8 — native header geometry and completed-thread layout

- 不再覆盖 Codex 原生固定 Header 的定位模式，修复 macOS 对话页标题、音乐、
  生命和魔力 HUD 因重复偏移产生的错位。
- 任务完成后只收起经过验证的空原生会话占位层，让短回答靠近输入框；流式输出
  期间保持 Codex 原生空间，完成后再恢复紧凑布局。
- 双平台渲染测试覆盖完成态、流式态和状态切换，防止后续 Codex DOM 调整重新
  引入回答后大块空白。

## 2.6.0.7 — live random settings

- Saving the random environment pool now updates the active renderer in place
  instead of rebuilding the skin, so the current environment and music session
  remain active.
- Added a manual “随机下一个” control and clarified the random-settings labels.
- Recolored the macOS native open-location button group so its controls remain
  visible on Terraria headers.

## 2.6.0.6 — native header HUD slot

- 音乐按钮、生命值和魔力值不再覆盖在全局 chrome 上，而是作为 Codex 原生
  Header 的直接 Flex 子项参与标题和操作按钮的宽度计算。
- 新任务与已有对话切换、会话 Header 重建时会迁移并复用同一个 HUD，保持当前
  音乐控制器和播放状态；仅在原生 Header 暂时不存在时使用短暂兜底。
- 移除标题栏 `padding-right` 魔法留白，长标题改为依靠原生 Flex 收缩和省略号，
  修复 macOS 与 Windows 对话页 HUD 穿模和错位。

## 2.6.0.5 — hot-upgrade HUD migration

- 热更新会识别并重建缺少统一 `.terraria-hud` 的旧版装饰 DOM，不再需要重启
  Codex 才能让音乐、生命值和魔力值使用同一套坐标。
- HUD 顺序固定为“音乐、生命值、魔力值”，修复 macOS 热更新后音乐按钮跑到
  红心和魔力星右侧的问题。
- Windows 共用渲染器同步加入相同迁移保护，并用双平台回归断言防止旧结构复发。

## 2.6.0.4 — native scroll anchoring and unified Terraria HUD

- 不再把 Codex 原生 `column-reverse` 会话滚动位置强制写成 `0`，修复任务结束后
  最后一条回答上移、输入框上方留下大块空白的问题。
- 音乐按钮、生命值和魔力值改为同一个 HUD 容器，以主内容区域为定位基准；
  长标题会为 HUD 留位并正确省略。
- 响应式窄窗口把音乐入口收成 44px 音符按钮，同时保留键盘焦点和有效点击区域。

## 2.6.0.3 — installed one-click upgrade identity

- 将 macOS 内部版本提升到可比较的 `2.6.0.3`，确保已经安装旧 `2.6.0`
  引擎的用户运行新包时进入升级流程，而不是因版本号相同跳过部署。
- 一键入口的已安装完整性检查现在要求受管目录同时包含 `VERSION`、
  `common-macos.sh`、安装器、一键脚本和控制台脚本；包内版本与运行时身份不一致时
  会在改动现有安装前失败。
- 新增 `--verify-installed-runtime` 回归：将安装源移走后，从隔离的
  `~/.codex/codex-dream-skin-studio` 受管副本验证版本和所有必需入口，避免后续
  再出现下载包更新但本地引擎没有真正升级的情况。

## 2.6.0 — 2026-07-25

### macOS 单一入口

- 面向用户的 ZIP 顶层只保留一个可执行入口
  `START-CODEX-TERRARIA.app`；隐藏引擎、说明文档与音乐仍随完整目录交付。
- 首次安装或升级需要关闭 Codex 时会先弹窗确认，取消不修改任何状态；同版本或
  更新版本已经安装时，重复双击同一入口会直接打开“Codex 皮肤控制台”。
- 启动 App 使用本地 ad-hoc 签名，不弹终端窗口；安装包不完整或脚本失败时会显示
  明确错误。安装后继续只保留 `~/Applications/Codex 皮肤控制台.app` 作为日常入口。

### macOS 资源与音乐迁移包

- 新增 macOS 构建器，将完整 Terraria 主题资源、
  透明 APNG 动画、通用架构控制台和本机已导入音乐一起封装。
- 交付物同时包含内层安装 ZIP、SHA-256 校验文件、首次使用和 macOS 安全确认说明；
  外层 `-DELIVERY.zip` 可直接复制到另一台 Mac。
- 新机器首次安装会写入随包音乐；升级时如目标机器已有音乐配置则保留原配置，
  不以打包机器的设置覆盖用户已有曲库。
- 构建器支持将音乐随包交付；公共发布包仍不包含、不下载 Terraria 原声。

### 极端细长伙伴过滤

- 血鳗、骨蛇、千足蜈蚣、银河织妖和飞龙的完整 Wiki 图片纵横比过大，在输入区
  安全框中只能看见一条或一小节；固定主题与全环境随机现已移除这 5 个候选。
- 渲染器继续按真实图片宽高兜底拒绝纵横比超过 `4.5:1` 的旧主题素材；伙伴刷新
  和环境重建生成器同步使用名称语义过滤，后续刷新不会把这些素材重新带回。
- 正常但偏小的完整怪物继续通过 tiny/small/wide 尺寸档清晰显示，不使用会暴露
  动画矩形画布的 CSS transform。

### 完整伙伴与小尺寸清晰显示

- 从森林夜晚、地下层、地下沙漠、地表腐化和地下腐化的伙伴池中移除 27 个
  多节怪独立头部、身体或尾部槽位；机械骷髅王、陨石怪、南瓜王等本身就是完整
  单位的图片继续保留。
- 固定环境和全环境随机同步继承过滤结果；刷新生成器也加入语义过滤，后续重新从
  Wiki 整理素材不会把残片重新带回。
- 载荷只为图片传递宽高数字。最大边不超过 16px 的伙伴使用 `96×76px` 绘制盒，
  17～24px 使用 `84×66px` 绘制盒；不使用 `transform`，继续保持像素化、懒加载
  和 APNG 透明合成。
- 实机验证腐化地表只剩 6 个完整伙伴，萤火虫和仙灵分别命中两档放大，距输入区
  和窗口右缘仍保持安全间距；全随机恢复为 44/44、10 分钟且音乐配置未变化。

### 控制台首页居中与像素图标

- 将首页入口、当前配置和使用说明作为一个完整内容组，在标题栏与底部状态条之间
  垂直居中并略向下偏移；默认 `980×690` 和最小 `820×600` 窗口均保持完整、
  无滚动、无状态条遮挡。
- 首页不再混用 SF Symbols。当前配置、三项统计和三条使用说明统一使用 Terraria
  环境球、音乐盒、齿轮与魔镜像素资源；“恢复官方外观”使用与返回出生点语义一致
  的魔镜，入口箭头改为本地绘制的像素阶梯箭头。
- 新增资源安装和字节一致性检查，并增加源码回归约束，防止首页重新出现通用
  地图、随机、播放列表、闪电、音符或返回系统图标。

### 动态伙伴透明合成

- 对 896 个动画引用（393 个不同动画）统一执行透明 APNG 规范化，伙伴、事件怪物、
  小动物和动画背景不再直接播放 GIF；原始 Wiki GIF 只作为可追溯的来源备份。
- 动态伙伴不再作为 CSS 背景绘制，改为由独立的原生图片元素承载，避免 Chromium
  在帧切换时暴露 GIF 的矩形处置画布；载荷通过明确的动画素材索引识别 APNG。
- 动态伙伴关闭额外的投影、滤镜、缩放和位移动画，保留素材自身动画；静态 PNG
  伙伴仍保留原有浮动和像素阴影。
- 运行时热更新会自动替换旧版伙伴容器，不需要重启 Codex。双平台渲染测试覆盖
  APNG 结构、无限循环、图片源同步、动画类型标记和旧容器迁移；macOS 实机抽查
  红魔鬼、光之女皇、飞翔荷兰人、小动物及动画背景均未再出现黑色矩形。
- 公开运行包只带 APNG，不重复携带未使用的 GIF 来源备份，避免双份素材增加体积。

### 控制台视觉收敛

- 原生控制台去除毛玻璃、大圆角、浮层阴影、悬浮缩放和宣传口号，改为不透明的
  Terraria 深色硬边面板、双层像素描边与克制的金色状态刻线。
- 首页三个入口缩成紧凑工具栏式卡片；“当前配置”和“使用说明”只保留真实状态与
  必要操作，不再用超高营销卡片填满窗口。
- 提高森林像素背景的可见度，并缩短音乐页空白面板；默认窗口和最小窗口仍无需
  滚动即可使用主要设置，环境表与随机池继续使用各自的原生滚动区。
- 新增源码回归约束，阻止玻璃面板、投影和英文宣传口号重新进入控制台。

### 同环境多背景

- 从 Terraria 官方 Wiki 的生物群系背景页整理 81 张背景，覆盖 29 个存在官方
  变体的环境；没有独立变体的事件和洞穴继续使用其准确的固定背景。
- 新增“进入环境后固定一张”和“停留期间定时轮换”两种模式。固定模式每次进入
  环境选择一张并保持不变；轮换模式可设置 1～60 分钟间隔。
- 背景继续按需加载：任意时刻只把当前环境的一张背景挂进页面，切换后立即释放
  旧引用，不会因 81 张素材增加常驻图片解码和 DOM 数量。

### 来世原声与播放策略

- 音乐设置新增“经典原声”“来世原声（缺曲回退经典）”和“经典与来世混合”。
  44 套环境全部映射到 Terraria 官方 Wiki 记录的 21 个来世音乐槽。
- 新增“继续换曲”和“固定一首循环”。固定模式在进入环境时选择一首，播放结束
  后仍循环该文件；继续换曲模式沿用顺序／随机列表行为。
- 来世音乐仍须用户导入自己合法持有的文件。项目源码和公开 ZIP 不包含、不下载
  也不重新分发任何 Terraria 音频。
- 旧版 `music.json` 与 `random-pool.json` 自动补齐新字段；所有背景、音乐和
  全环境切换设置均原子持久化并可在运行中的 Codex 热更新。

### 双平台一致性

- macOS 原生控制台和 Windows 托盘同步提供背景模式、背景间隔、原声版本及曲目
  行为设置；两端使用同一份 44 环境映射、81 背景索引和渲染回归用例。

- SwiftBar 菜单栏标题恢复调色板图标，并加入静态回归检查，避免升级后只剩 `Skin ON` 文本。

- 菜单栏与 `status-dream-skin-macos.sh` 不再依赖 `/usr/bin/python3`（macOS 12.3+ 默认不预装）读取主题名与运行状态，改用纯 shell 解析；此前在未装 Xcode 命令行工具的机器上，主题名会退化成 id、`--json` 状态直接失效

### 安全

- CDP 端点必须由已验证的官方 Codex 可执行文件或其子进程监听；WebSocket 还会校验 loopback、page ID、路径、无重定向，并安全处理畸形消息和发送异常。
- 主题配置与图片使用真实路径 containment，拒绝 symlink 越界、空文件、超过 16 MB、单边超过 16384 px 或超过 50 MP 的图片；主题展示文本拒绝换行和控制字符。
- AppleScript 动态内容全部通过 argv 传递；SwiftBar 过滤主题 ID、文件名和菜单文本，避免主题元数据改变菜单属性或命令参数。
- `config.toml` 只按严格 UTF-8 读取，拒绝 NUL、歧义多行 TOML、重复 `[desktop]`，通过用户级锁、原始字节核验和同目录原子替换保护中文配置与并发写入。
- 暂停和恢复会在 TERM/KILL 前后核验 watcher 的 PID、启动时间、Node 和 injector 路径；不匹配的进程绝不结束，已确认 watcher 若无法停止则保留 state 并中止，不再报告假成功。

- 覆盖每套预设的可注入性与播种幂等、首页/任务 renderer、早期注入、主题原子切换、中文与 CRLF/BOM 配置往返、非法 UTF-8/NUL/TOML 拒绝、路径穿越、symlink 越界、控制字符和像素炸弹。
