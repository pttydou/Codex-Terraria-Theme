# Codex 皮肤升级体检与修复流程

每次 Codex 更新、皮肤更新、兼容性修复从这里开始。目标是主动找问题、按根因修复、留下可复用证据，避免用户逐个指出白边。

皮肤通过 CDP 接入 Codex 私有页面，无法承诺永久免维护；稳定属性也不是官方永久 API。可以减少依赖面、自动发现回归，让更新只改对应适配器、共享配色或生命周期。“全身修复”指完成检查矩阵并处理发现的问题，不是脚本盲目改 CSS。

## 1. 统一入口

在本项目目录执行：

```bash
npm run checkup
```

常用变体：

```bash
npm run checkup -- --port 9341
npm run checkup -- --offline
npm run test:browser
# 从空白新会话首页开始，允许工具切换设置页面：
npm run checkup -- --port 9341 --interactive
```

- 顺序执行源码/资源测试、所有 `tests/*-browser.test.mjs`、live doctor、兼容性报告和当前页检验。一项失败仍继续后面的独立检查。
- 默认只读抽检当前主窗口，不切页、刷新、切主题或启动 watcher。浏览器回归使用独立无头 Chrome；现有夹具阻断网络，不控制用户窗口。
- 自动寻找本机 Playwright 和 Google Chrome。缺少依赖标待补环境，不计通过，不自动安装。可用 `PLAYWRIGHT_MODULE=/绝对路径/index.mjs CHROME_PATH=/绝对路径/Chrome npm run checkup` 指定；显式路径失效时不偷偷换依赖。
- `--offline` 只做源码与独立浏览器回归，live 项保持未测。
- 报告在 `~/Library/Application Support/CodexDreamSkinStudio/reports/checkups/<时间>/report.md`、`report.json`。`--output-root DIR` 可换体检目录；单页 HTML/截图仍在原 `reports/`，保留同场景历史比较。
- 保存命令、退出码、耗时、日志、代码/主题配置哈希、实际客户端版本和主题。二进制资源由资源测试/地图来源清单检查；代码指纹不是全部素材和官方应用的完整备份。
- **退出 0=自动项通过；1=存在失败；2=待复核、环境缺失或未测。均不等于完整验收。** 自动报告 `completeAcceptance=false`，交互完成后另填验收结论。

单处检查用 `npm run inspect -- --open`，菜单巡检用 `npm run inspect:overlays -- --open`。工具细节与限制见 [INSPECTION.md](INSPECTION.md)。

## 2. 更新前后建立基线

1. 核实安装目录、Codex 版本、磁盘皮肤与实际 renderer 版本、暂存主题、注入模式、CDP 端口和唯一主窗口。`session=manual` 且无 watcher 可以是用户有意选择，不能擅自改成常驻。
2. 更新前有条件就跑体检；保存原主题/音乐/伙伴/布局，备份将改的源码。更新后、修改前再跑一次。缺旧基线就标缺失，不套用历史通过截图。
3. 同版本号也可能代码不同，要保留文件指纹。安装目录可能无 Git metadata，不能声称同步了远端；需要远端对照时核实 macOS 分支/目录及提交，不能照搬 Windows 文件。
4. 比图固定主题、环境、窗口宽度、缩放、路由和交互状态。随机背景、正在输出文字、后台限速需记录为干扰，稳定后重测。
5. 用户主题源为 `~/Library/Application Support/CodexDreamSkinStudio/theme`，不能用 `assets/` 示例主题替代。真实会话截图留本机，公开回归使用去内容夹具。

**工具自身也要防覆盖：** Codex 客户端更新与皮肤安装包更新是两件事。皮肤安装器会整体替换安装目录；在本轮改动进入远端 macOS 发行包前，旧安装包可能覆盖新入口。更新皮肤包前保存本流程、AGENTS和工具源码到仓外；更新后先核实 `npm run checkup` 是否还存在。缺失时按保存的补丁与新源码合并，不整目录回滚。当前本机接续入口在 `~/.codex/codex-dream-skin-local/`，本轮工具快照和证据在 `evidence/2026-10-22-checkup/`。本轮未提交或发布远端。

## 3. 完整验收矩阵

由维护者执行并填写证据，未访问的页面保持未测。菜单巡检覆盖 11 个已知入口；`inspect:pages` 另覆盖允许的内部设置子页、滚动底部和两轮首页往返，仍不是全应用遍历。

| 检查面 | 实际操作与预期 | 已有工具/补测要求 |
| --- | --- | --- |
| 新会话 | 未发送首页，离开再返回；四边/背景/字体/建议区/输入框正常 | A5；当前页检验。发送后正常不能替代发送前 |
| 已有会话 | 长回复、代码块、滚动、侧栏会话悬停；文字、操作条、提示清晰 | A6；当前页检验 |
| 弹层与表单 | 项目首页菜单、嵌套表单、图标选择；关闭重开；普通/hover/focus/选中态可读 | 11入口巡检 + popover/popup-label浏览器回归；不最终创建或提交 |
| 选区浮条 | 选中文字→取消→再选；按钮/分隔线正常，无遗留节点 | ST-011；selection回归。菜单巡检不代替真实选区 |
| 设置 | 主题涉及的子页，尤其使用情况和计费；进入退出至少2轮 | A7；inspect:pages 四次采样；检查左右及返回首页不先白后蓝 |
| 快速聊天 | 实际打开/关闭2轮，独立外壳/输入区/关闭按钮及返回主窗正常 | A8；真实目标，prewarm/伙伴overlay不能替代 |
| 文件与布局 | 文件左右、分栏/全宽、拖分隔条，窄/常用/宽窗口；输入区跟随所在窗格、不跳动、无槽缝 | ST-010；workspace18组合 + 实机逐帧；文件全屏另验 |
| 环境与资源 | 森林/洞穴/太空，固定与随机；改过的环境逐一看 | A4；地图90组与来源哈希；整图铺满，音乐/伙伴不丢失 |
| 音乐与伙伴 | ready→playing→off、切环境后再打开；确认实际可播放及伙伴存在 | A9；入口存在不能给播放项满分 |
| 刷新生命周期 | 可恢复页面真实刷新，再进设置/快速聊天；无首帧白闪、延迟字体跳变或长期安全模式 | A10；100/500/1200/2500/5000/8000ms及首末截图 |

当前页四次采样从**调用检验时**开始，不是页面加载时；刷新首帧要另做时序采样。像素探针不覆盖全部内部白框、深蓝错误和字体字形，必须看图。图片/渐变对比度 `unknown` 要人工复核，不能当通过，也不能一律重新染色。

### 用户指定的升级必考题（2026-10-28 更新）

这三题分别记录成绩，不再用“白边0”“无overflow”或总分90分替代。每题：0=复发，1=未测/证据不足，2=本轮源码回归与相关实机复核均通过。三题必须各为2，才能通过用户指定专项；分数不加到A1–A10里稀释原标准。写明本轮覆盖的环境/状态，没操作的完整矩阵项目仍为未测。

| 题目 | 必查触发与判定 | 自动回归与实机证据 |
| --- | --- | --- |
| ST-016 侧栏与主背景接缝 | 地图/宽幅背景；首页/会话/设置；侧栏展开/拖宽。侧栏右侧不能有20px贴图竖带，主内容紧邻侧栏，拖拽有效 | sidebar-edge-browser 24组；inspect 的 sidebarEdge；实机修前/修后同环境边界截图及8秒复检 |
| ST-017 输入框外围黑边 | 空闲、文件已更改、进度行展开；全宽/文件左/文件右。检查输入框上方、左右留白、底部是否露出原生纯色底板/渐变；输入、状态按钮正常且尺寸稳定 | footer-paint-browser 18组；inspect 的 footerDecorations；实机输入区截图及8秒复检 |
| ST-018 额度弹层及说明文字可读性 | 打开用量、关闭重开、悬停；检查额度来源/标题/描述，不能只检查按钮。0/500/1200/2500/8000ms不变回深色；主按钮、警告色正常 | popup-label-browser 18组；巡检 usage-menu；probe 的 popupText 独立采样；复杂背景必须看图，未采到说明不得算通过 |

失败时按各ST根因查绘制层，不通过挪动输入框、缩小侧栏或染掉业务按钮来消除色块。去内容浏览器夹具与真实用户页面是两类证据，不能互相冒充。

## 4. 根据根因选择修复层

| 证据/触发 | 优先定位与修复原则 | 旧错题 |
| --- | --- | --- |
| 磁盘更新，renderer仍旧 | 注入/载荷/会话模式；先同步运行代码并回读 | ST-007 |
| main/Composer无命中、update-adapter | 发现适配器、路由required；优先稳定data/语义，回退集中登记，保持自有marker接口 | ST-003/004 |
| 节点命中但标记丢失，稍后变色 | ownership/observer/清理；不按已染色结果反推资格，重复扫描应幂等 | ST-001 |
| 背景正常，文字/图标不可见 | 同类组件共享配色；成对查背景、color、text-fill、透明度、SVG及交互态 | ST-002/005/006/009/011 |
| 输入宽度交替、分栏鬼畜 | 原生布局与脚本回写；CSS随所在窗格，消除ResizeObserver反馈，同时核对宽度是否合理 | ST-010 |
| 首帧正常后闪白、字体延迟 | 早期样式与挂载生命周期；分别测首次加载/热注入/切路由/清理重入，不靠延长超时掩盖 | ST-004 |
| 墙块缝隙、随机才复发 | 来源→固定预设→随机生成→暂存；修生成入口、去重键/哈希/裁切，不只换最终png | ST-012 |
| 截图时问题消失 | 测试改变现场；用inspect保留焦点/悬停，旧verify截图会Escape/移鼠标 | ST-008 |

`recommendedAction=none` 只说明当前结构无已知缺口，视觉错误仍需处理。`inspect-fallback`、`wait-and-recheck` 都要复核，不能因命令退出0就关闭问题。

每个缺陷走同一闭环：**复现并保留修前证据 → 查旧ST → 根因 → 最小责任层修改 → 同触发复测 → 同类组件及反例回归 → 写ST和报告**。有新失败继续修；测试干扰则修正条件，不能改业务界面迎合误报。常规已授权修复无需逐处重复问用户。

严重度：P0=核心输入无法使用/持续布局震荡；P1=可复现白闪、关键控件不可读、入口/资源丢失；P2=非关键视觉偏差。无法复现要写条件与缺口，不造修前失败；低影响纯文档改动不写镜像实现的测试。

## 5. 完成标准与复盘

- 修后重跑受影响回归；最终交付前执行一次checkup。浏览器文件按 `*-browser.test.mjs` 命名自动纳入；普通源码用例仍登记 `tests/run-tests.sh`。
- 按 [SELF_TEST_PLAYBOOK.md](SELF_TEST_PLAYBOOK.md) A1–A10评分。**≥90分、无未解决P0/P1、必测路径有本轮证据、warn/unknown均复核**才称完整macOS合格。任一必测项未测，即使工具100分也只能写增量范围。
- 采样期间源码/暂存主题变化，统一报告标待复核，应以最终版本重跑，不能拼接两套基线。
- 恢复并回读原主题、随机/固定模式、音乐、伙伴、窗口/文件布局、注入模式。测试不发送真实消息、创建内容或改账号；需要真实发送才可复现时注明缺口，再安排该场景。
- 新根因记录ST编号、触发、漏测原因、修复位置、修前/修后证据、下次检测；复发在原条目追加日期与原因。修复后应有能抓到同类问题的回归，而非只增加一个例外选择器。
- 更新同一需求交接；报告和原始截图留本机，归档文档保留来源、时间、实际状态及必要去内容证据。

## 6. 执行周期与下一步减负

| 时机 | 执行范围 |
| --- | --- |
| 每次Codex/皮肤升级 | 前后基线 + 统一体检 + 完整矩阵 |
| 局部修复 | 修前证据、针对回归、相关页面；最终体检，明确增量范围 |
| 未升级但复发 | 查原ST，核对运行代码/主题和时序，不重加旧补丁 |
| 连用一周或下次维护 | 回看待复核、误报、漏测，将高频问题纳入回归；无需定期改正常代码 |

已落实：共享弹层色组、自有标记/兼容性诊断、早期字体、安全降级、布局去反馈、地图来源及生成保护、五套独立浏览器回归；本轮增加统一入口、代码指纹、失败日志及待补清单。

后续优先级（仍是计划，不冒充已实现）：

1. **收拢宿主选择器到适配器。** 验收：一个属性改名只改对应适配器，视觉CSS无需重写。
2. **收拢组件色组及所有交互态。** 验收：新弹层复用背景/文字/图标配对规则，原生告警和内容颜色不被误染。
3. **装饰用自有容器隔离。** 评估Shadow DOM用于音乐/伙伴等，不重新实现宿主输入/设置。验收：布局变动不影响装饰，卸载无残留节点/监听器。
4. **补真实应用交互自动化。** 优先设置往返、快速聊天、选区、分栏和刷新时序；入口缺失标未测。验收：自动抓到历史“先正常后坏”，无需用户指出。
5. **评估原生主题作为基础层。** 先核实当前官方客户端实际支持的接口，再决定迁移字体/基础色。验收：停用注入后基础可读性仍在，用户偏好可恢复。

每次选一个有证据的切口推进，不为“稳定性”同时重写整套外观。架构现状见 [STABILITY.md](STABILITY.md)。
