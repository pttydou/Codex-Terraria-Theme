# 本机皮肤检验工具

升级和修复的总流程见 [UPGRADE_CHECKUP.md](UPGRADE_CHECKUP.md)。`npm run checkup` 统一执行源码/全部浏览器回归/doctor/兼容报告/当前页检验，生成本机 Markdown 和 JSON；本文说明单项工具。工具返回 0 也可能有待复核，完整验收不能只看退出码。

适用版本：2.7.27 起，macOS。目标是每次更新后尽快发现失效范围，并留下可重复比较的证据。

## 怎样使用

打开 **Codex 皮肤控制台 → 皮肤检验**。保持待测 Codex 页面不动，完成后会自动打开本机报告。无须关闭会话。也可以双击项目目录里的 `Inspect Codex Dream Skin.command`，或执行：

```bash
npm run inspect -- --open
# 选择特定 CDP 端口；显式参数优先于环境变量和状态文件
npm run inspect -- --port 9341
```

工具不发送消息、不切换环境、不重载页面，不发 Escape、不移动鼠标。默认检测唯一的 `app://-/index.html` 主窗口；辅助窗口/快速聊天预热页面不作为主窗口。出现多个主窗口时生成失败报告，避免悄悄选错。

报告默认保存在：

```text
~/Library/Application Support/CodexDreamSkinStudio/reports/
  时间戳-唯一编号/
    report.html       可打开的结果
    report.json       评分、排查建议和未测项
    samples.json      四次结构/样式摘要与逐帧输入区几何，不读取聊天正文
    first.png        首次采样后的截图
    last.png         最后一次采样后的截图
  latest.json        最新报告位置
```

截图会包含当前屏幕显示的会话内容；只落盘、不上传。CSS 中的图片 URL/内嵌图片被替换成摘要，文字检查只记录控件或弹层说明序号、颜色和坐标，不保存文字内容。历史记录不会自动删除；需要释放空间时可自行删除旧的时间戳目录。

## 交互巡检（2.7.28 起）

进入 Codex 的**项目新会话首页**，关闭已有弹窗，点击 macOS 控制台的 **交互巡检**，或执行：

```bash
npm run inspect:overlays -- --open
```

此入口会移动鼠标、点击并用 Escape 关闭自己打开的弹层；执行期间约一分钟不要操作 Codex。原来的“皮肤检验”仍只读当前页面。已有弹层时交互巡检保留现场并停止；多个主窗口时也不会猜测目标。

常驻顶部toolbar参与视觉检查，但不视为阻塞菜单；选区浮条和真正弹窗仍阻塞启动。添加项目会先悬停项目标题，待按钮展开后重新测量；新版直接显示表单时不点“下一步”，设备来源通过表单内菜单检查。详见ST-019。

固定路径：输入框项目选择、首页项目选择、添加项目设备/来源步骤、添加项目名称/源文件夹步骤、项目图标、运行位置、分支、权限、模型/推理、账户菜单、额度来源与用量说明，共 11 个入口。创建流程只点“下一步”，不点击最终创建、选择文件夹或其他选项，不发送消息、不修改配置。

2.7.30 起，当前页检验也识别选中文字后出现的 `selection-actions` 浮条及语义 `toolbar`，检查表面像素和按钮文字/图标。上面 11 项交互巡检不会自动选择聊天正文：需先手动选中已有回复中的文字，再运行“皮肤检验”，检查后取消选择并重复一次。不要点击“添加到对话”等实际动作。未打开浮条不能算已验收此项，详见 ST-011。

报告在 `reports/walks/时间戳-唯一编号/`，包含 `walk.json`、HTML、每项首末截图以及约 0/500/1200/2500ms 的实际采样。采样从弹层挂载后开始，不等于捕获绘制首帧；独立浏览器夹具另测首帧规则。缺少入口为“未测”，点击后未出现预期弹层为“失败”，浅色或低对比候选为“疑似问题”；“已检查”仅表示当前自动规则未报警，仍需看截图和待复核数量。

退出码 2 包含未测入口、失败、疑似或流程错误；控制台的 `--console` 只保证报告能打开，不表示合格。报告暂不自动做交互场景历史差分；按相同入口、主题、窗口尺寸手动比较历史截图。完整验收分数仍按 A1–A10，不将 11/11 入口执行率当作应用满分。

ST-018 增补：用量弹层的额度来源等普通 `div/p/标题` 也会采样，嵌套弹层和控件文字去重；隐藏、裁切、遮挡、禁用和可编辑内容跳过。说明文字采样使用独立额度，避免被长侧栏的控件挤掉。用量入口采不到说明文字会报错；后台滤镜/图片导致 `unknown` 时仍需看图，不能计为通过。

## 首页与设置巡检（2.7.33 起）

从**没有草稿、没有弹层的新会话首页**运行，执行期间保持客户端不动：

```bash
npm run inspect:pages -- --port 9341 --open
# 连同源码、浏览器、兼容检查一起运行：
npm run checkup -- --port 9341 --interactive
```

工具按当前版本实际入口巡检 29 个允许的内部设置子页，检查内容顶部和可滚动底部，再往返复测通用、使用情况、外观、伙伴。每处按 0/500/1200/2500ms 采样并保存首末截图；缺入口标未测，未知/外部入口不点击，不切换设置值、不发送消息。完成后返回首页；遇到用户切页或新增输入立即停止，不抢回原页面。报告位于 `reports/pages/`（统一体检时在对应 checkup 目录内），退出 0=自动项通过、1=失败、2=待复核或有未测项。

当前页检验同时检查标题卡片宽度、标题/项目按钮越界。页面识别只使用可见容器，设置名称取 `aria-current="page"`，不会把隐藏缓存首页或全部侧栏菜单当作当前页。没有文档级溢出不代表标题卡片内部正常。设置巡检不覆盖快速聊天、文件分栏、刷新和音乐播放，这些仍按总流程专项验证。

## 怎样读结果

**当前页自动抽检分数**独立于 [SELF_TEST_PLAYBOOK.md](SELF_TEST_PLAYBOOK.md) 的 A1–A10 完整验收分数。通过得分，失败/疑似/待复核/未测均不得分。即使自动项 100 分，也不代表设置、快速聊天、环境切换、刷新与音乐播放已验收。

| 检查 | 分值 | 证据和边界 |
| --- | ---: | --- |
| 连接身份 | 10 | 验证本机 Codex 进程/CDP，精确选择唯一主窗口 |
| 运行一致性 | 15 | 磁盘版本、实际注入版本、暂存主题与当前主题一致 |
| 兼容性契约 | 15 | 四次采样的适配器状态、样式启用和安全模式；报告给出处理方向 |
| 标记 | 10 | 根据路由要求检查可见 main / Composer / settings 数量；设置页不强制会话 Composer |
| 溢出 | 10 | 四次文档横纵溢出；不等于检查了所有内部滚动容器 |
| 稳定性 | 10 | 四次比较关键表面位置/尺寸、字体和颜色；2.7.29 起同时逐帧观察输入区 2.5 秒，检查跳变与越过聊天窗格。页面/窗格改变、少于 30 帧、间隔超过 250ms 或不足 2.4 秒标待复核；不代表刷新首帧 |
| 文字可读性 | 10 | 每次至多 160 个可见且启用的按钮/链接/选项文字片段，另有独立上限 160 个弹层静态标题/描述文字片段和 160 个弹层 SVG 色样；考虑 text-fill、透明度和祖先背景；普通文字 4.5:1、大字和图标 3:1；低于阈值是疑似问题 |
| 边缘 | 5 | 从首末截图真实像素抽查窗口外缘 0/2/8 像素；检查侧栏向外延伸伪元素、输入框外底板/渐变是否覆盖背景；采样已打开弹层内部像素和输入/文件夹等大块内层背景。近白色是疑似问题，正常浅色装饰也可能命中 |
| 装饰入口 | 10 | Terraria 音乐按钮、状态和可见伙伴容器存在；不替代播放/点击验证 |
| 证据 | 5 | 四次样本、首末两张截图；缺失不算通过 |

渐变、图片、伪元素、滤镜等导致文字背景无法可靠计算时，标 **待复核**。截图检查覆盖近白色外缘与可识别弹层；侧栏接缝另检查原生伪元素的外延背景绘制（ST-016），输入区检查原生底板/渐变（ST-017），不要求异常是白色。仍不能发现所有内部白框、蓝色闪变、错误字体字形、空内容或资源加载故障。正在流式输出或主动操作页面可能改变控件集合，稳定性会提示复测。

报告在最近 50 份记录中查找相同主题、环境、路由（设置页含可识别的 panel slug）、窗口尺寸、缩放以及原生分栏布局/聊天窗格位置的最近一次记录，只比较检查结论。它标出上次通过而本次失败/疑似的检查项，不做整图像素差分。每项附 ST 编号，可到错题本找既有修复方案。

逐帧探针只读 DOM，最多 600 帧，3.2 秒截止时取消动画帧和计时器。后台窗口被限速时不能判成稳定；请把待测窗口保持可见并重测。该探针只观测输入区几何，不识别所有色彩闪烁。左右换位、拖动分隔条及全宽/分栏切换仍须实际操作后各测一次，见 ST-010。

CLI 退出码：`0` 表示报告生成且无硬失败（仍可能待复核），`2` 表示检测发现失败，`1` 表示工具错误。控制台内部的 `--console` 在失败报告已生成时返回成功，以便 UI 能打开报告，不代表皮肤通过。

## 每次更新如何执行

1. 改代码前后按 UPGRADE_CHECKUP.md 运行 `npm run checkup`，包含源码、所有浏览器回归及只读实机检查。
2. 打开当前会话，运行检验，保存首份报告。
3. 在项目新会话首页运行交互巡检，并逐张复核截图；再按错题本依次检查新会话、设置、快速聊天、代表环境和刷新。主窗口里的每个待测页面可再次运行检验；快速聊天生命周期仍需要专项验证。
4. 有失败或疑似时，按报告的 ST 编号排查；修复后在同场景重跑。保留旧报告，不能用新分数覆盖旧事实。
5. 完整清单未完成时写“增量检查”，不宣称整套皮肤合格。每次 Codex 更新执行完整清单；同类问题反复三次或每周复盘一次。

此工具不依赖配置中心；不修改 Codex 配置和暂存主题。要停用工具，停止点击入口即可，工具不安装后台定时任务。

## 开发者验证

`npm test` 包含检测器的纯逻辑和 PNG 行为用例；浏览器回归统一用下面的命令。会寻找本机已安装的 playwright-core 和 Chrome，也可显式指定：

```bash
npm run test:browser

PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs \
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
npm run test:browser
```

此命令自动发现全部现有 `*-browser.test.mjs`：检测器、弹层、选区、布局、地图；使用临时配置启动独立 Chrome，夹具阻止网络，不连接用户 Codex。逐套日志和 browser-report.json 保存在打印的临时目录，可用 `--report-dir DIR` 指定新的输出目录。缺依赖或零测试不会通过。

需要额外验证报告布局时，单独运行 `tests/inspection-browser.test.mjs`，同时设置 `PLAYWRIGHT_MODULE`、`INSPECTION_REPORT=/absolute/path/report.html`，可加 `REPORT_PREVIEW=/absolute/path/preview.png` 保存预览。统一浏览器入口会清除这些可选预览环境变量及 BEFORE_CSS，避免上轮调试参数混入正式回归。夹具通过不能写成所有真实 Codex 页面通过。
